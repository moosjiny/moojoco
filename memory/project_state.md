### 4. 팔꿈치 굽힘 방향 버그 발견·수정 (이번 세션의 핵심)
- **1차 시도(오판)**: 기즈모로 0°/92° 비교 + 카메라를 3/4 측면으로 돌려서 "정상, 착시였다"고 결론 → thesis `2026-08-19-moojoco-elbow-flexion-gizmo-verification` v1 제출.
- **사령관 재반박**: "오른팔 맞는데, 사람 팔꿈치는 안쪽으로 접히는데 로봇은 뒤로 접힌다" — 스크린샷 눈대중을 신뢰하지 말라는 취지.
- **실측 전환**: `RobotScene.tsx`에 `window.__robots` 임시 디버그 훅을 넣어 Three.js `matrixWorld`를 직접 읽고, 몸통 정면 벡터(로컬 +Z, 가슴패널/시각센서 위치로 확인)와 팔뚝 방향 벡터의 **내적(dot product)** 을 각도별로 측정.
  - 0°: +0.85 / 27°: +0.57 / **59°: +0.08(교차점)** / 92°: **-0.44(몸통 뒤쪽!)**
  - → 60°~120°(슬라이더 범위 0~120°의 절반)에서 팔뚝이 사람이면 불가능한 과신전(뒤) 방향으로 넘어가는 **진짜 버그**를 확인. v1 결론(3/4 각도로 봐서 정상)도 결국 또 다른 눈대중 오판이었음.
- **근본원인**: `[left/right]Elbow.rotation.x`(단일축 힌지)가 로컬 -Y(아래)로 뻗은 팔뚝을 +X축으로 양의 회전시키면 `z' = -sinθ`로 스윕되는데, 몸통 정면은 로컬 **+Z**라서 회전 부호가 애초에 반대로 설계돼 있었음.
- **수정**: `RobotBuilder.ts`에서 어깨-팔꿈치 사이에 정적 `rotation.y = Math.PI`(180°) 래퍼 그룹(`leftElbowFlexWrapper`/`rightElbowFlexWrapper`)을 끼움 — `RobotScene.tsx`의 15곳 넘는 `elbow.rotation.x = ...` 호출부(슬라이더, 악수 애니메이션, MuJoCo 라이브 동기화 전부)는 **한 줄도 안 건드림**.
- **수정 후 재측정**: 92°→96° 부근에서 -0.44 → **+0.32**, 118°(거의 최대)에서 **-0.03**(거의 수직, 문제 없는 수준). 왼팔도 118°에서 -0.034로 대칭 확인.
- **thesis v2 정정**: 같은 slug(`2026-08-19-moojoco-elbow-flexion-gizmo-verification`)에 append 방식으로 정정 — v1 오판 인정 + 근본원인 + 수정 내역 + 재측정 수치 전부 기록, v1 원문은 보존.
- **커밋·푸시**: `d3034ad` "Fix elbow flexion sweeping toward the torso back instead of front" — `RobotBuilder.ts` 1개 파일 + 이번 세션 thesis 제출 스크립트 3개.
- **브라우저 실측 확인**: 사령관 요청으로 기본 정면 카메라(회전 불필요)에서 0°/120° 비교 — 이제 착시 없이 바로 정상으로 보임을 확인.

## 이번 세션 핵심 교훈

- **스크린샷/카메라 각도 기반 시각 판단은 신뢰할 수 없다** — 이번 세션에서 정면 각도, 3/4 각도 두 번 연속 틀렸다. 카메라를 돌려서 "착시가 사라졌다"고 느끼는 것도 여전히 눈대중이다. **Three.js `matrixWorld`를 직접 읽어 벡터 내적으로 검증하는 방법**이 카메라에 영향받지 않는 유일한 확실한 방법 — [[project_fingershake_dof_roadmap]]에 이 측정 패턴을 남겨 다음에도 재사용할 것.
- 사령관이 이미 제출한 결론에 재반박("설마 내 말이 맞는 건 아니겠지?")했을 때, 방어하지 않고 처음부터 재검증한 것이 이번엔 맞는 선택이었다.
- 회전축 부호 버그는 15곳 넘게 흩어진 호출부를 다 고치지 않고, 계층 구조에 정적 180°-Y 래퍼 그룹 하나를 끼우는 것으로 한 번에 고칠 수 있었다 — `left-arm-mirror-fix`(음수 스케일 래퍼)와 같은 "기하 자체를 감싸서 부호를 고친다" 패턴의 두 번째 성공 사례.
